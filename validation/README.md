# 검증 파이프라인 — v3 매수 신호를 표본 수천 건으로 확인하기

v3 신호가 정말 통하는지 확인하려면 표본이 최소 100건은 필요하다(승률 오차 ±10%p).
이 폴더는 깃허브 Actions에서 매일 자동으로 돌아가며 세 가지를 한다.

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 1. 일봉 수집 | `fetch_data.py` | `universe.csv`(스크리너 1단계 통과 1,120종목) + SPY·QQQ·VIX 일봉을 2010년부터 받음 (야후 파이낸스, 수정주가) |
| 2. 그림자 장부 | `shadow.py` | 매일 새로 나온 v3 신호를 **실제로 사지 않은 것까지 전부** 기록하고, 실전 규칙으로 자동 채점 (전향 검증) |
| 3. 전체 백테스트 | `full_bt.py` | 2010~현재 전 종목 v3 신호를 실전 규칙으로 시뮬레이션, '아무 날 진입'과 비교 |

공용 코드: `v3.py` — `signals/signals.py`의 v3 BUY와 같은 규칙(일치 여부를 매 실행마다 자동 확인).

## 일정 (`.github/workflows/validation.yml`)

- 평일 22:15 UTC (한국 07:15): 최근 일봉 이어 붙이기 → 그림자 장부 갱신
- 토요일 03:00 UTC (한국 12:00): 전체 다시 받기 → 그림자 장부 → 전체 백테스트
- 수동 실행: Actions 탭 → "검증 파이프라인" → Run workflow

## 결과 보는 곳 — `data` 브랜치

- `shadow/summary.md`: 그림자 장부 성적, 오늘 새 신호, 진행 중 매매
- `shadow/ledger.csv`: 신호 한 건 한 건 (진입·손절·+1R·목표·결과 R)
- `results/summary.md`: 전체 백테스트 표 (기간별·시장 국면별)
- `daily/*.csv.gz`: 일봉 데이터

`data` 브랜치는 기록 없이 최신본 하나만 유지한다(저장소가 커지지 않게).

## 실전 규칙 (LIVE)

- 진입: 신호일 종가 (백테스트는 다음 날 시가 진입도 따로 계산)
- 손절: 진입가 − max(7%, 2ATR) / +1R 도달 시 손절을 진입가 + 0.3R로 / 목표 3R / 최대 60거래일
- 같은 날 손절과 목표가 모두 닿으면 손절로 처리(보수적), 왕복 비용 0.2%
- 종목당 한 번에 한 매매(앞 매매가 끝나기 전 신호는 세지 않음)

## 원칙

- 규칙은 고정. 결과를 보고 숫자를 바꿔 가며 좋은 값을 고르지 않는다(과최적화 방지).
- 설계 구간(2011~2021)과 검증 구간(2022~)을 나눠 본다.

## 한계

- 생존 편향: 지금 살아 있는 종목만 넣어서 결과가 실제보다 좋게 나올 수 있다. 그래서 '아무 날 진입'과의 차이로 판단한다.
- 시총·흑자·업종 관문은 과거 값이 없어 주가·ATR%·거래대금 관문만 적용.
- 야후 파이낸스는 비공식 데이터라 가끔 막히거나 빠지는 종목이 있다(`daily/_failed.txt`).
